# Contributing to Veyra

Thank you for contributing to Veyra.

## Before you start

- Check existing Issues and Discussions before opening a new one.
- For bugs, use the bug report template.
- For feature proposals, use the feature request template or start a Discussion when the idea needs community feedback.
- Never commit API keys, passwords, tokens, private URLs, or environment files.

## Development workflow

1. Fork the repository or create a feature branch if you have repository access.
2. Install dependencies with the package manager documented in the README.
3. Configure local environment variables from the provided example files.
4. Make focused changes.
5. Run the available build and test checks.
6. Open a pull request against `main`.

## Pull requests

Please include:

- What changed
- Why it changed
- How it was tested
- Screenshots for meaningful UI changes
- Any migration or environment-variable changes

Keep pull requests focused and avoid unrelated formatting or refactoring.

## Security

Do not disclose security vulnerabilities in public Issues or Discussions. Follow `SECURITY.md` for private reporting.

## Code of conduct

Be respectful, constructive, and professional. Harassment, discrimination, personal attacks, and malicious behavior are not acceptable.
